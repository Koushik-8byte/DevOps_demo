Target Server IP: 32.192.235.131

Author: Infrastructure Notes

Part 1: Conceptual Architecture & The "Why"
Before jumping into the commands, it is crucial to understand how modern web traffic flows. In production systems, application servers (like Node.js, Python, or Java apps) are never exposed directly to the public internet. Instead, they sit safely behind an infrastructure layer controlled by Nginx.

1. What is a Web Server?
A web server is software responsible for accepting HTTP requests from clients (browsers) and returning responses (HTML, images, or JSON data). Nginx is highly optimized for this because it uses an event-driven, asynchronous architecture. Unlike older servers (like Apache) that create a new system thread for every single visitor, a single Nginx worker process can handle hundreds of thousands of concurrent connections simultaneously with minimal RAM overhead.

2. Why use a Reverse Proxy?
A standard proxy protects a client (e.g., a VPN hiding your home computer). A Reverse Proxy protects the server.

Security: It acts as a shield. The public internet only ever communicates with Nginx. Your actual application code runs privately on local internal ports (127.0.0.1), entirely hidden from malicious port scans and direct attacks.

Application Decoupling: Your application developers don't have to write complex network routing, caching, or rate-limiting code. Nginx handles the network layer, letting your apps focus strictly on business logic.

3. Why use a Load Balancer?
If your website runs on a single server node and that node crashes, your entire business goes offline. If your traffic spikes, that single node will run out of CPU/RAM.

Horizontal Scaling: Instead of buying a bigger, expensive server (Vertical Scaling), you deploy multiple cheap server instances (Horizontal Scaling).

High Availability (Fault Tolerance): Nginx constantly monitors your backend app pool. If a backend node dies, Nginx instantly redirects traffic to the surviving healthy nodes. The end-user experiences zero downtime.

4. What is SSL Termination?
Encryption is mathematically expensive. If your Python or Node.js apps have to decrypt and encrypt every data packet via HTTPS, their performance plummets.

Nginx SSL Termination: Nginx handles the intensive cryptographic handshake at the front door. Once Nginx safely decrypts the incoming HTTPS traffic, it passes the plain-text HTTP request over the internal local network to your apps. The internal transfer happens instantly, and your backend apps spend zero CPU cycles on encryption.

Part 2: Step-by-Step Implementation Runbook
Step 1: Firewall Configuration (Cloud Gatekeeper)
Before Nginx can process traffic, your cloud provider's network firewall (AWS Security Groups) must be instructed to open the public ports.

Port 80 (HTTP): Required so clients can reach your server initially when typing a plain URL.

Port 443 (HTTPS): Required for all encrypted, secure web traffic.

Step 2: Provision the Backend Application Pool
We deploy three lightweight Python instances to mock a distributed production microservice environment.

Create decoupled directories to store static assets for each isolated application node:

Bash
mkdir -p ~/nginx-project/server{1,2,3}
Write custom web pages into each node directory. This allows us to track exactly which node is responding during testing:

Bash
echo "<h1>Node 1 (Port 3001) - Active Secure Node</h1>" > ~/nginx-project/server1/index.html
echo "<h1>Node 2 (Port 3002) - Active Secure Node</h1>" > ~/nginx-project/server2/index.html
echo "<h1>Node 3 (Port 3003) - Active Secure Node</h1>" > ~/nginx-project/server3/index.html
Spin up the listeners in the background using the & terminal operator:

Bash
cd ~/nginx-project/server1 && python3 -m http.server 3001 --bind 127.0.0.1 &
cd ~/nginx-project/server2 && python3 -m http.server 3002 --bind 127.0.0.1 &
cd ~/nginx-project/server3 && python3 -m http.server 3003 --bind 127.0.0.1 &
Why --bind 127.0.0.1? This locks the Python apps to the local loopback interface. No one on the internet can bypass Nginx and access ports 3001–3003 directly.

Step 3: Generate the Cryptographic Keys (SSL)
Because we are configuring this without a registered domain name, we generate a Self-Signed Certificate via OpenSSL.

Bash
sudo openssl req -x509 -nodes -days 365 -newkey rsa:2048 \
-keyout /etc/ssl/private/nginx-selfsigned.key \
-out /etc/ssl/certs/nginx-selfsigned.crt \
-subj "/CN=32.192.235.131"
Line Breakdown:

req -x509: Specifies that we want a self-signed identity certificate rather than a certificate signing request.

-nodes: (No DES) Instructs OpenSSL to skip protecting the private key with a passphrase. This allows Nginx to restart automatically without a human typing a password every time the server reboots.

-days 365: Sets the cryptographic validity window to 1 year.

-newkey rsa:2048: Generates a brand new 2048-bit RSA mathematical key pair (highly secure).

-subj "/CN=32.192.235.131": Binds your public IP directly as the "Common Name" for the certificate identity.

Step 4: Write the Master Nginx Configuration
Clear out the default vendor landing page configuration:

Bash
sudo rm /etc/nginx/sites-enabled/default
Create your new infrastructure configuration module:

Bash
sudo nano /etc/nginx/sites-available/loadbalancer.conf
Insert the following production configuration block:

Nginx
upstream backend_pool {
    # Defines the target server cluster. By default, Nginx uses 'Round Robin'
    # passing connections sequentially down the list.
    server 127.0.0.1:3001;
    server 127.0.0.1:3002;
    server 127.0.0.1:3003;
}

# BLOCK 1: Insecure Traffic Interception
server {
    listen 80;
    server_name 32.192.235.131;

    # Returns an HTTP 301 (Permanent Redirect) header.
    # Forces the client's browser to instantly drop the HTTP connection
    # and re-request the page using secure HTTPS.
    return 301 https://$host$request_uri;
}

# BLOCK 2: Encrypted Traffic Termination & Reverse Proxy
server {
    listen 443 ssl;
    server_name 32.192.235.131;

    # Load the cryptographic parameters generated via OpenSSL
    ssl_certificate /etc/ssl/certs/nginx-selfsigned.crt;
    ssl_certificate_key /etc/ssl/private/nginx-selfsigned.key;

    location / {
        # Hands off the decrypted traffic to our upstream group defined above
        proxy_pass http://backend_pool;

        # CRUCIAL PROXY HEADERS:
        # Without these, the backend app thinks all traffic originates from Nginx (127.0.0.1).
        # These inject the real client data into the request header packet.
        proxy_set_header Host $host;                                    # Preserves original domain/IP requested
        proxy_set_header X-Real-IP $remote_addr;                        # Passes the actual visitor's public IP
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;    # Appends IP list if passing multiple proxies
        proxy_set_header X-Forwarded-Proto $scheme;                     # Tells the app if user connected via HTTP vs HTTPS
    }
}
Enable the configuration module by symlinking it into the active directory:

Bash
sudo ln -s /etc/nginx/sites-available/loadbalancer.conf /etc/nginx/sites-enabled/
Test the configurations for missing characters or syntax mistakes:

Bash
sudo nginx -t
Safely restart Nginx to push all network changes live:

Bash
sudo systemctl restart nginx

When you decide to scale this system up to use a public domain name (yourdomain.com) instead of a raw IP address in the future, follow this quick reference card:

Value: 32.192.235.131

Configuration Realignment: Open /etc/nginx/sites-available/loadbalancer.conf and update the server_name variables:

Nginx

Run sudo nginx -t and sudo systemctl reload nginx.

Automate Globally Trusted SSL: Run Certbot to destroy the temporary self-signed keys and fetch official, globally trusted certificates from the Let's Encrypt Certificate Authority:

Bash
sudo certbot --nginx -d yourdomain.com -d www.yourdomain.com
Once Certbot finishes running its automated verification, your browser will replace the "Not Secure" alert with a clean, fully verified lock icon. Your transition to production is complete!
